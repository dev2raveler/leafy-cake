# 레터링 케이크 주문 프로토타입 초안

## 매장 운영 방식

- 수령 방식은 매장 픽업으로 한다.
- 단일 매장에서 사용하는 것으로 한다.
- 고객이 주문을 요청하면 매장이 수동으로 전체 금액 입금을 확인하고 주문을 확정한다.
- 회원 가입은 제외한다.

## 고객 주문

- 고객 화면은 모바일 화면을 우선으로 한다.
- 고객은 케이크 목록에서 썸네일 이미지, 이름, 가격을 보고 케이크를 선택한다.
- 고객은 케이크 상세 페이지에서 케이크 이미지와 이름, 설명을 확인한다. 옵션 (크기, 맛)을 선택하고 실시간으로 가격을 확인한다. "주문하기" 버튼을 누른다.
- "주문하기" 버튼을 누르면 아래에서 드로우어가 나타난다. 픽업 가능한 일자를 달력에서 선택하면 픽업 가능 시간대가 표시된다. 시간대를 선택하면 "다음" 버튼이 활성화 된다.
- "다음" 버튼을 누르면 레터링 문구와 추가 요청 사항을 입력하고 주문자 이름과 연락처를 입력하면 "완료" 버튼이 활성화된다.
- 드로어우가 닫히고 주문 내용을 한 번 더 확인한 뒤 요청을 보낸다.
- 접수 화면에서 주문번호와 현재 상태를 확인한다.

## 매장 주문 관리

- 매장 화면은 모바일 화면을 우선으로 하되, 데스크 탑에서도 지원하도록 반응형으로 한다.
- 매장은 주문 목록에서 픽업 일정과 주문 상태를 확인한다.
- 주문을 열면 디자인, 옵션, 레터링 문구, 고객 연락처를 볼 수 있다.
- 주문 상태는 접수 대기 → 주문 확정 → 제작 중 → 픽업 준비 → 픽업 완료 순으로 바꾼다.
- 제작이 어려운 주문은 사유를 기록하고 접수 거절로 처리한다.

## 첫 프로토타입에서 확인할 것

- 고객이 케이크를 고르고 픽업 시간을 정해 주문을 요청할 수 있다.
- 매장 주문 목록에 해당 주문이 나타나고, 매장이 상세 내용을 확인해 상태를 바꿀 수 있다.
- 고객 화면에서 매장이 바꾼 주문 상태를 확인할 수 있다.
- 예시 케이크와 주문 데이터를 사용하며, 실제 결제와 알림 없이 프론트엔드에서 흐름을 검증한다.
